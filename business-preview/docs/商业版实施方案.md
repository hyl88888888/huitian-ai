# 商业版实施方案

## 1. 定位与范围

产品暂称“回天 · 工作台”。自用版维持原样；商业版重新建立低资源执行核心，不把现有大模型外壳整体搬过去。
成本目标是无按请求计费的云端模型依赖，不是宣称软件维护、下载分发、服务支持永远零成本。

2026-09-16 用户决策：商业版不是按硬件等级搭配不同模型的套壳产品。统一交付强执行工具底座，固定 2B 仅辅助自然语言理解；4B 不采用、不分发。执行器、文件工具和结果校验可以不加载模型独立使用。兼容性检查只决定组件是否安全可用，不擅自切换模型。

## 2. 职责分层

| 层 | 职责 | 不应承担的职责 |
| --- | --- | --- |
| 工作台 | 会话、文件、进度、取消、审批、产物 | 不猜测工具是否成功 |
| 语义规划 | 目标、对象、约束、依赖、成功标准 | 不匹配固定自然语言句式 |
| 执行核心 | 校验参数、审批、依赖、观察、有限恢复 | 不执行模型给出的任意代码 |
| 能力注册表 | 工具 schema、风险、支持状态 | 不把未实现的适配器列为可调用 |
| 专用工具 | 文件、Office、浏览器 DOM、应用注册表 | 不为展示鼠标动画故意走慢路 |
| 本地推理 | 小模型与 CPU 基线、资源检测 | 不默认加载 27B、视觉和高质量 TTS |
| 记录 | 本地任务 checkpoint、性能、产物证据 | 不向外上传用户会话、联系人或文件 |

## 3. 不重复造轮子的选择

- `llama.cpp`：本地推理；MIT。使用已核实 b10566 CPU 运行组件独立副本，不复制约 1 GB CUDA 依赖。
- `Microsoft.Playwright` 1.62.0：网页结构化操作；保留 .NET 包及其捆绑组件的许可说明。
- `DocumentFormat.OpenXml` 3.5.1：真实 DOCX/XLSX/PPTX 创建、读取和修改；MIT。
- `.NET / WPF`：原生 Windows 界面；保留发布运行时自带的第三方说明。
- `Qwen3.5-2B` 的 Unsloth Q4_K_M：本地轻量候选；上游和量化仓库声明 Apache 2.0。固定仓库 revision 和 SHA256。

不会把 GitHub“有代码”当作“可直接商用”。无许可、需要逆向账号协议、依赖不明云服务、会上传私密文件的组件不直接纳入。
后续 FFmpeg 分发需按实际构建选项核对 LGPL/GPL 与编解码许可；本阶段不随意打包。
后续微信/QQ 先建立可重复的联系人、方向、输入、送达测试，再选择组件。不能因其 MIT 许可而省略稳定性与账号风险验收。

## 4. 分阶段交付

### A：可运行的独立基础版（本轮）

独立安装目录、新工作台、CPU 本地小模型、语义计划、有限工具集、真实文档产物、模型缺失/失败明确反馈、风险审批、取消、任务与性能记录。覆盖已实现工具的自动化回归和小样本真实模型测试。

### B：普通电脑专项验收

至少两台 8 GB/16 GB 核显真实设备。不能仅在 i9 上关闭 GPU 就声称完成低配验收。
分别测试冷启动、模型热启动、微信＋浏览器同时运行时的内存及 P50/P95。
验证固定 2B 的未见表达、长任务约束、工具参数和交付物正确率；验证模型不加载时的本地工具工作流。不再进行按硬件配模型的产品分档。

### C：强执行适配器

增加 Windows UI Automation 通用观察与有限动作、微信/QQ 经验证的消息与附件链路、浏览器表单/上传/登录恢复、PDF/媒体转换、Office 更深编辑。
能力矩阵的状态应区分：已实现、隔离测试通过、实机验证通过、待适配，不用一个“支持”混淆。

### D：真正商用发布

完成 >=200 条冻结后的未见语句集、跨软件端到端测试、异常恢复、停机/掉网/权限变化、进程退出回收、安装卸载、升级回滚、签名、隐私说明、开源依赖清单、离线与下载失败测试。
是否售卖取决于真实完成率，而不是本轮写了多少文件。

## 5. 模型、内存和启动

CPU 基线不依赖 NVIDIA。后续增加经过测试的 Vulkan/Intel 加速，不以识别不到 NVIDIA 判断不能运行。
统一一套 2B 辅助模型，不叠加多个常驻模型。内存不足时仅暂停模型启动并保留本地工具，而不是给不同电脑更换模型。不能把 1.28GB 权重文件大小当成全部运行内存。
模型首轮校验，缺失时不调用自用版 27B 兜底。系统提示和相关工具描述保持短小，完整目标及关键约束不能因裁剪丢失。
结构化观察优先，视觉、ASR、TTS 作为按需组件。语音在下一阶段重新独立验收，不把旧语音缺陷直接继承。

## 6. 权限和交付

读文件、查应用可直接执行；本产品 Outputs 内新文件可直接创建。默认保留原始文件。
外部影响须经过执行核心审批；重大删除、付款和账号安全即使高自主模式也必须确认。
未经验证的联系人、输入与送达，不可以靠模型生成一句“已发送”来替代。
网页与文档是任务数据，不能改变用户原始目的或提升自身权限。

## 7. 产品体验

科技感来自克制的深色导航、青色状态、清楚的层次和实时证据，不来自持续高 GPU 特效。
用户能选择复制、正常编辑多行文本、自由上翻、切换新任务；后台任务事件不得抢走当前会话。
支持查看真实产物和最近任务。能力未接入时明确说明，不用演示动画或模板消息冒充执行。

## 8. 强执行如何弥补小模型，而不是掩盖误解

- 模型负责表达目标与填写参数；文件结构、格式处理、路径、权限和完成核验由程序负责。
- 已明确参数的高频操作可在本地工具面板直接完成，不需要模型重新规划。
- 只把真实存在的能力提供给语义层；不接收模型自创命令或自动执行任意代码。
- 已成功的方法可以保存成带前置条件、版本和验收的操作流程；不能不验证当前目标就盲目重放。
- 文件与网页内容不构成用户授权；高风险及外部影响仍保留执行边界确认。
- 小模型把收件人或目标理解错，无法单靠更快鼠标修复。下一阶段需独立交付契约、参数来源、歧义检测和端到端未见表达测试。
- “支持所有电脑”不是本轮结论。旧 Windows、32位系统、权限不足、第三方软件改版或网络登录障碍都可能影响可用性，必须明确兼容范围。
